# スキルの自己改善規約

**スキルは実行して終わりではない。失敗したら、その失敗をスキル自身に書き戻す。**
書き戻さなければ同じ失敗が何度でも繰り返される。

エージェント定義には既に「既知の失敗パターン」（sonnet-uplift の品質ゲート）があるが、
スキル側には同等の仕組みがなかった。本規約はそれを埋める。

## 適用範囲

| 対象 | 「失敗の記録」節 |
|------|----------------|
| `execution_type: agent-teams` / `hybrid`（ワークフロー系） | **必須** |
| `execution_type: standalone` / `subagent` | 推奨（失敗が起きた時点で追加する） |

ワークフロー系を必須とするのは、複数のサブエージェントが絡んで失敗の原因が追いにくく、
かつ同じ失敗が並列に増幅されるため。

## 節の書式

各スキルの Version History の直前に置く。

```markdown
## 失敗の記録と反映

このスキルの実行で失敗・見落とし・誤りが起きたら、**その場で下表に追記する**。

### 記録する条件

- 出力に誤りがあり、ユーザーから訂正された
- 手順どおり実行したのに目的を達成できなかった
- 検証をすり抜けた欠陥が後から見つかった
- サブエージェントの結果を鵜呑みにして誤りを通した

### 既知の失敗パターン

| 日付 | 失敗の内容 | 原因 | 反映した対策 |
|------|----------|------|------------|
| YYYY-MM-DD | {何が起きたか} | {なぜ起きたか} | {本文のどこをどう直したか} |

### 反映の手順

1. 上表に1行追加する
2. **本文の該当箇所を直す**（チェックリスト項目の追加、手順の明確化など）
3. 機械的に検出できる失敗なら `scripts/` の検証へ追加し、回帰テストを書く
4. Version History にバージョンを上げて記録する
```

## 書くもの・書かないもの

| 書く | 書かない |
|------|---------|
| **実際に起きた**失敗 | 想定される失敗の先回り |
| 原因まで特定できたもの | 「注意する」で終わる精神論 |
| 本文への反映とセットのもの | 記録しただけで本文を直していないもの |

**表に行を足すだけで本文を直さないのは、記録ではなく放置である。**
表は「本文のどこを直したか」の索引として機能させる。

## 検証

`scripts/validate-skill-self-improvement.py` が以下を機械的に確認する。

- ワークフロー系スキルに「失敗の記録と反映」節があるか
- 節がある場合、表のヘッダが規定の4列（日付・失敗の内容・原因・反映した対策）か

pre-commit hook からも実行される。
