# レポートのテンプレート

人が読むレポートを作るときに、種類に合うものを選んで使う。見た目の値は[レポート・文書のデザイン基準](../report-design-standard.md)に合わせてある。議事録はここに置かず、`meeting-agenda` スキルのテンプレートを使う。

## 種類の選び方

| 種類 | ファイル | 使う場面 | 読み手 |
|---|---|---|---|
| 進捗報告 | [status-report.html](status-report.html) | 週次・月次で進み具合と課題を報告する | 上長、依頼元、関係チーム |
| 経営向け報告・判断依頼 | [executive-brief.html](executive-brief.html) | 経営層に判断を求める。印刷して A4 で 1〜2 枚に収める | 経営層、決裁者 |
| 調査レポート | [research-report.html](research-report.html) | 技術・市場・制度などを調べ、結論と推奨をまとめる | 依頼元、判断者 |
| 障害報告 | [incident-report.html](incident-report.html) | 障害の影響、原因、再発防止を報告する | 経営層、利用者の窓口、開発・運用チーム |
| 数値分析レポート | [kpi-analysis-report.html](kpi-analysis-report.html) | KPI の目標と実績を比べ、要因と打ち手を示す | 事業責任者、運用担当 |
| 提案・比較検討 | [proposal-comparison.html](proposal-comparison.html) | 複数の案を比べ、推奨を示して判断を依頼する | 決裁者、提案先 |
| テスト結果報告 | [test-report.html](test-report.html) | テストの結果を集計し、公開してよいかを判断する | 開発責任者、公開の判断者 |
| プロジェクト完了報告 | [project-closure-report.html](project-closure-report.html) | 案件の終わりに成果と計画との差をまとめ、引き継ぐ | 依頼元、運用の引き継ぎ先 |

## 使い方

1. 使うファイルを作業場所へコピーする。このフォルダのファイルは書き換えない。
2. `[案件名]`、`[YYYY/MM/DD]` のように `[ ]` で囲んだ部分を実際の内容へ置き換える。使わない行と節は消す。書き終えたら `[` で検索し、残りが無いことを確かめる。
3. 状態の語は HTML のコメントにある候補から選び、`status-ok` などの class も合わせる。
4. キーカラーを差し替えるときは、`<style>` の先頭の `--key`・`--key-strong`・`--key-bg` だけを変える。グラフの第 1 系列も `--key` に従う。`--key` と `--key-strong` は文字にも使うので、白地と `--key-bg` の両方で 4.5:1 以上を確かめ、届かないときは色を濃くして合わせる。
5. オフラインで配るときは、Google Fonts の `<link>` の行を消す。書体は OS の日本語ゴシック体になる。
6. `kpi-analysis-report.html` のグラフの線は仮の形である。座標、`[値]`、`aria-label` を実データへ置き換える。

依頼者の指定、提出先の様式、`DESIGN.md` があるときの扱いは基準の[優先順位](../report-design-standard.md#優先順位)に従う。その場合も[下限](../report-design-standard.md#下限)は守る。例外は、提出先が様式を固定していて変えられないときだけである。

行を足すときに使う class は次のとおり。

- `.callout`: 結論の枠
- `.status` と `.status-ok`・`.status-warn`・`.status-caution`・`.status-err`・`.status-info`: 状態の表示
- `.table-wrap`: 表の外枠。幅が足りないときはこの内側だけが横に動く
- `.num`: 数値と日付の列を右揃えにする
- `.table-dense`: 列が多い表を 14px にする
- `.table-few`: 行数が少ない表のセルの上下を 20px にし、印刷で分割しない
- `.table-actions`: 次のアクションの表（内容・担当・期限）
- `.note`: 注記と出典

## Markdown で書くとき

`document-creation` の経路では HTML を使わず、次の見出しの並びで書く。`#` に文書タイトルを、`##` に各項目を書き、作成者と作成日はタイトルの直後に置く。書式は基準の[媒体ごとの適用](../report-design-standard.md#媒体ごとの適用)に従う。

| 種類 | `##` の並び |
|---|---|
| 進捗報告 | 結論と全体の状態 / KPI 表 / 完了したこと / 課題とリスク / 次の予定 / 依頼事項 |
| 経営向け報告・判断依頼 | 判断してほしいこと / 結論と推奨 / 背景 / 選択肢の比較 / リスク / 次のアクション |
| 調査レポート | 要約 / 目的と範囲 / 方法 / 結果 / 考察 / 推奨 / 限界 / 出典 |
| 障害報告 | 概要と影響 / 時系列 / 原因 / 対応 / 再発防止 / 残課題 |
| 数値分析レポート | 要約 / KPI 一覧 / 推移のグラフと元データ / 要因 / 打ち手 |
| 提案・比較検討 | 課題 / 案の比較表 / 費用と効果 / 推奨 / スケジュール / 判断の依頼 |
| テスト結果報告 | 判定 / 対象版と環境 / 結果の集計 / 不具合一覧 / 未確認事項 / 判断 |
| プロジェクト完了報告 | 成果 / 計画と実績 / うまくいったこと / 課題 / 引き継ぎ |

`report-publish` は広告の日次・週次レポートの専用経路で、Doc の名前、副題、Chatwork の投稿先が固定されており、前回の広告レポートの投稿も削除する。上の 8 種の配信には使わない。
