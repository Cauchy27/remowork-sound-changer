# 技術情報の調べ方

**ライブラリのAPI・フレームワークの仕様・設定方法・バージョン間の差異を調べる際は、記憶に頼らず Context7 MCP で最新のドキュメントを取得する。**

学習データは古い可能性があり、よく知られたライブラリでも仕様が変わっている。「知っているつもり」で書いた設定やAPIが動かない事故は、この確認を飛ばしたときに起きる。

## 手順

1. `resolve-library-id` でライブラリIDを解決する
2. `query-docs` でドキュメントを取得する

## 使う場面

| 場面 | 使う |
|---|---|
| ライブラリのAPI・引数・戻り値を確認する | 使う |
| フレームワークの設定ファイルの書き方を調べる | 使う |
| バージョン移行の破壊的変更を確認する | 使う |
| CLI ツールのオプションを調べる | 使う |
| 自分たちのコードの調査・リファクタリング | 使わない（Read / Grep で足りる） |
| 一般的なプログラミング概念の説明 | 使わない |

## 補足

Context7 が対象ライブラリを持たない場合は、公式ドキュメントを WebFetch で直接読む。**推測で書かない**という原則が本質であり、Context7 はその手段のひとつである。
