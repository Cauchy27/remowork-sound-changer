# 人への確認・相談の書式

松川への確認、上司へのレポート、仕様書の確認事項では、確認欄を次の2つに分ける（松川指定・2026-10-06）。進捗・実行結果は通常の報告欄に置き、この欄には今回の判断・確認に必要な内容だけを書く。

「人間」は実際の判断者名へ置き換えてよい。松川が判断した内容なら「松川が判断した点：」とする。人物名は確認先ではなく判断した本人を示す。判断者が複数なら人物別に分けるか「人間が判断した点：」のまま各項目に判断者を添える。人物名が分からない内容を、宛先から推測して誰かの判断にしない。

```text
[info]
松川が判断した点：
- [判断した内容／判断者／発言・正本の根拠]

不安で確認したい点：
- [確認したいこと／不安の理由と影響／回答してほしい内容]
[/info]
```

「人間が判断した点」は、本人の発言や決定記録で確認できる判断を書く。仮置きの採用なら仮置きと明記し、その有効範囲を示す。AIの提案・推測・裁量内の実装選択、検証で分かった事実だけを、人の判断として書かない。判断者や根拠が不明なら「不安で確認したい点」へ置く。

「不安で確認したい点」は、判断・解釈・根拠の不足や矛盾について、何を答えてほしいかまで具体化する。AIの提案を添える場合は未採用の案と明記する。必要な場合だけ、回答待ちで止める作業と、並行して進める作業を添える。中間チェックを自動的な承認待ちに変えず、未決事項に依存する部分だけ保留する。

人が選んだ案について一部だけ不安がある場合は、判断の内容を前者、未解決の問いを後者に置き、同じ説明を全文で二度書かない。既に回答や正本から決まる内容を質問へ戻さず、必要な要約か参照だけを置く。確認先が松川・社長・齋藤さん等で異なるときは宛先を明記し、その人に必要な内容だけを見せる。

確認欄を出す場合は2つの見出しを残し、該当する項目がなければ「なし」とする。両方ともなければ欄全体を省き、確認のための確認を増やさない。既存の項目番号や分類が必要なら区分の内側に置く。判断・根拠・未決事項の正本は既存文書やカードのままとし、この確認欄を別の正本にしない。

Chatwork等の `[info]` が使える媒体は上の枠を使う。Asana・Markdown・仕様書・Google Docs等では同じ2つの見出しを通常の見出し・太字で表示し、`[info]`・`[/info]` を装飾タグとして渡さない。媒体の表示方法を変えても、区分と内容は同じにする。

例：人が「STGでの中間チェック中も後続実装を進める」と決めているなら前者に置く。「FBで共通ルールが変わる可能性があり、どの作業に影響するか確認したい」は後者に置き、影響する作業だけを示す。
